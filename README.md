# Budget Daily (PWA)

Минималистичное offline-first PWA для ежедневного контроля бюджета:
- доходы/расходы;
- стартовый баланс по месяцам;
- прогноз остатков по каждому дню месяца;
- дневной лимит и проекция остатка;
- распределение конкретного дохода по диапазону дат;
- резервная копия: сохранение всех данных в JSON-файл и восстановление из него (меню «⋮» в шапке).

## Stack

- Vite + React + TypeScript
- `vite-plugin-pwa` (`registerType: autoUpdate`)
- Хранение: `localStorage`

## Запуск

```bash
npm install
npm run dev
```

## Сборка

```bash
npm run build
```

Результат будет в `dist/`.

## PWA и offline

- Service worker регистрируется в `src/main.tsx` через `virtual:pwa-register`.
- После первого открытия и кэширования статических ассетов приложение работает офлайн.

## Деплой на GitHub Pages

1. Для репозитория вида `https://github.com/<user>/<repo>` выстави `base` через переменную:

```bash
VITE_BASE_PATH=/<repo>/ npm run build
```

2. Публикация в ветку `gh-pages`:

```bash
npm run deploy
```

По умолчанию `deploy` использует содержимое `dist/`.

## Структура данных

```ts
settings: {
  payDays: number[];            // дни зарплаты, например [5, 20]; [] — календарные месяцы
  opening: { date: "YYYY-MM-DD"; amount: number }; // известный остаток на начало дня
  distribution: {
    enabled: boolean;
    mode: "fromStart" | "fromToday" | "fromDate";
    fromDate?: string;
  };
  customCategories: {
    income: string[];
    expense: string[];
  };
}

transactions: Array<{
  id: string;
  type: "income" | "expense";
  date: "YYYY-MM-DD";
  amount: number;
  category: string;
  note?: string;
  spread?: {
    enabled: boolean;
    startDate: "YYYY-MM-DD";
    endDate: "YYYY-MM-DD";
  };
}>;
```

Старый формат (`month`, `startBalanceByMonth`) переносится автоматически: последний ненулевой
стартовый баланс становится точкой отсчёта `opening`.

## Периоды

Бюджет делится не на календарные месяцы, а на зарплатные периоды: от дня зарплаты до дня
перед следующей. Если день зарплаты выпадает на субботу или воскресенье, выплата (и начало
периода) переносится на пятницу; день больше длины месяца становится его последним днём.

Остаток на начало периода переносится из предыдущего: `opening.amount` ± все движения между
`opening.date` и началом периода. Ручная правка остатка делает начало этого периода новой
точкой отсчёта.

## Алгоритм расчёта таблицы дней

1. Генерируются все дни периода.
2. Для каждого дня считаются суммы `income/expense`.
   - Обычная транзакция учитывается в свою дату.
   - Доход с `spread.enabled=true` делится равномерно по диапазону `startDate..endDate`
     (в копейках; остаток от деления уходит в последний день, чтобы сумма сходилась точно).
3. `balanceEnd = balanceStart + income - expense`, по дням в хронологии.
4. Дневной лимит считается от точки отсчёта (`fromStart`/`fromToday`/`fromDate`) так, чтобы
   остаток ни в какой день не уходил в минус — деньги не тратятся раньше, чем пришли:
   - берётся самый «узкий» день `k`, где `(остаток + доходы − расходы до k) / число дней` минимально;
   - до этого дня лимит равен этой величине, дальше расчёт повторяется с того, что осталось;
   - если даже без трат остаток уходит в минус, лимит 0 и показывается, сколько не хватает.
5. Все денежные значения округляются до 2 знаков (лимит — вниз).
